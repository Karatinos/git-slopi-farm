# Договорнячок
### Категория Web

### Описание задания

Я очень люблю футбол, узнал, что собираются провести реконструкцию первого московского матча между командами "Сокольники - Быково". Однако результат может быть другой.

Трансляция будет завтра, но говорят, что у комментаторов заранее пишут, какая команда победит. Мне очень нужно узнать, кто победит. Очень нужно. Очень.

Адрес сервиса: http://HOST:PORT/

# Решение

Перейдем по ссылке указанной в описанием. Попадаем на главную страницу сайта "Московский футбол".

![[Pasted image 20260917222649.png]]

Видим интересующий нас матч между "Сокольники" и "Быково". Перейдем к нему и посмотрим, что тут есть. 

![[Pasted image 20260917222937.png]]

На странице `/matches/67` видим информацию про то когда, где состоится матч, краткую информацию про него, номер - 67 и статус трансляции. Также нам доступны страницы прогнозов на матч и новостей. Перейдем на вкладку профиля. 

![[Pasted image 20260917222957.png]]

При нажатие на кнопку "Войти" нас перекинет на страницу для авторизации.

![[Pasted image 20260917223012.png]]

При попытке войти с неправильными кредами выпадет ошибка `401 Unauthorized {"detail":"Incorrect username or password"}`. Регистрируемся, пароль должен быть >= 8 символов.

![[Pasted image 20260917223107.png]]

Нас перекидывает в профиль. Тут мы видим наше имя, роль, возможность изменить имя и информацию о себе. Если отследить наши запросы, например, через BurpSuite, то можно увидеть что профиль создается со следующими параметрами:

```json
{
	"id":14,
	"username":"QuackQuacky",
	"role":"fan",
	"commentator_id":null,
	"display_name":null,
	"bio":null
}
```

Видим понятные поля `username`, `role`, `display_name`, `bio`. `id` - скорее всего то, какой мы пользователь по счету. Также видим поле `commentator_id`, с учетом того, что наша основная цель связана с комментаторами, стоит обратить внимание на это. Можно сделать предположение, что полю присваивается значение не `null`, если пользователь является комментатором. 

Попробуем создать пользователя и сразу присвоить ему `commentator_id` и `role`. Отправим POST-запрос на `/api/v1/auth/register` с телом:

```json
{
	"username":"CommentatorGazMyas",
	"password":"qwertyui",
	"commentator_id":11,
	"role":"commentator"
}
```

Пользователь создастся, и мы даже получим токен, однако он все равно будет иметь "role":"fan","commentator_id":null. Пока что перейдем дальше. 

Этот таск вдохновлён ситуацией, произошедшей на ЧМ FIFA. Про нее можно почитать [здесь](https://bobdahacker.com/blog/fifa-hack). В той ситуации при регистрации аккаунта на одном поддомене, аккаунт добавлялся в тенант Microsoft Entra, который управлял всеми внутренними платформами FIFA. В нашем же случае мы будем двигаться не в сторону поддоменов, а в сторону подпапок.

Попробовав несколько типовых вариантов по типу `/admin` и т. д., можно выявить закономерность, что при неправильно указанном пути нас просто перебрасывает обратно на главную страницу. Если вы догадаетесь, благодаря контексту таска, можно сразу угадать что страницу `/commentator`.

Однако лучше действовать через более надежный метод, нежели игра в угадайку. 

Чанки- это фрагменты кода, на которые разбивается приложение в процессе сборки. Вместо одного огромного JS-файла мы получаем несколько файлов поменьше. Можно увидеть их, например, через F12 -> Network

Файл содержит код для комментаторского раздела приложения. В нем есть API-клиент для комментаторских эндпоинтов, проверка ролей, криптографические операции (AES-GCM шифрование/дешифрование), скрытые данные про исход матча.

Просто поменять значения полей мы не можем из-за подписи токена. 

Во вкладке профиля мы могли поменять значения `bio` и  `display_name` Открываем BurpSuite, включаем захват пакетов и пробуем изменить профиль.

Видим при отправке запрос типа PATCH, который передает новые параметры `bio` и  `display_name`. Он просто изменяет данные о нашем профиле. Попробуем вместе с этим изменить поле `role`. Ранее мы смотрели динамические js-чанки. Оттуда мы знаем что при проверке мы должны иметь поле `role` со значения `admin` или `commentator`.

```json
{
	"display_name":"quacky",
	"bio":"kryaaa",
	"role":"commentator"
}
```

Если попробовать сейчас посмотреть исход матча - ничего не получится. Вспоминаем, что при обращение по API, матчи имели поле `commentator_id`. Через изменение профиля попробуем поменять его на тот, что мы видели в информации про матч: `"commentator_id":12`. 

```json
{
	"display_name":"qua",
	"bio":"kry",
	"commentator_id":12

```
