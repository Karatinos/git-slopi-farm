    <div class="head">
      <span class="badge b-P"><span class="tick t-P"></span>API</span>
      <div class="metas"><span class="meta">JSON-RPC 2.0 over HTTP - programmatic access to factordb</span></div>
    </div>
    <div class="body">
      <p class="hint" style="margin:0 0 10px">All calls are JSON-RPC 2.0 sent as an HTTP <code>POST</code> to <code>/rpc</code> - at <code>https://factordb.com/rpc</code> or <code>https://factordb.com:4059/rpc</code>, both the same service. The body is a request object (or an array of them for a batch); the response mirrors it.</p>
      <pre style="overflow-x:auto;background:var(--st-u-bg,#f4f4f5);padding:10px 12px;border-radius:8px"><code>curl -s https://factordb.com:4059/rpc \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"get_number","params":{"target":{"expr":"2^131-1"},"detail":2}}'</code></pre>
      <p class="hint" style="margin:10px 0 0">Response: <code>{"jsonrpc":"2.0","id":1,"result":{…}}</code>, or <code>{…,"error":{"code","message"}}</code> on failure.</p>
    </div>

    <div class="body" style="border-top:1px solid var(--hair)">
      <p class="fieldlabel">Command-line client</p>
      <p class="hint" style="margin:0 0 6px"><code>fdb</code> wraps every method on this page as a subcommand - numbers and factors, proofs, certificates, sequences, statistics, downloads and your account - with human-readable output by default and the raw JSON result on request. It can also drive an aliquot sequence forward with local gmp-ecm, reporting the factors it finds (<code>fdb seq advance</code>).</p>
      <pre style="overflow-x:auto;background:var(--st-u-bg,#f4f4f5);padding:8px 12px;border-radius:8px"><code>fdb number 2^127-1 --full
fdb report 1427247692705959880439315947500961989719490561 2^61-1
fdb download C 60 --count 100 --random</code></pre>
      <p class="hint" style="margin:6px 0 0">Source: <a class="link" href="https://github.com/mtvb/factordb-cli" rel="noopener noreferrer">github.com/mtvb/factordb-cli</a> (Rust, GPL-2.0; <code>cargo install --path .</code> builds the <code>fdb</code> binary).</p>
    </div>

    <div class="body" style="border-top:1px solid var(--hair)">
      <p class="fieldlabel">Addressing (the <code>target</code> parameter)</p>
      <p class="hint" style="margin:0">Many calls take a <code>target</code>, which is either an id or an expression:
        <code>{"id": 42}</code> &nbsp;or&nbsp; <code>{"expr": "10^80+7"}</code>.
        Expressions accept <code>+ - * / ^ %</code>, <code>!</code> (factorial), <code>#</code>/<code>##</code> (primorial),
        <code>I(n)</code>/<code>lucas(n)</code>, the shortcuts <code>M</code>/<code>F</code> and <code>b,n+</code>/<code>b,n-</code>,
        named functions such as <code>Q(n)</code> (Perrin), <code>@(n)</code> (the n-th prime) and others, a reference to a
        stored id <code>#&lt;id&gt;</code>, and parentheses. See the full
        <a class="link" href="/syntax.php">expression syntax &amp; functions</a> reference.</p>
    </div>

    <div class="body" style="border-top:1px solid var(--hair)">
      <p class="fieldlabel">Authentication</p>
      <p class="hint" style="margin:0 0 6px">Anonymous access works for reads within the default limits. To act as your account - higher limits, certificate upload - send your API token:</p>
      <pre style="overflow-x:auto;background:var(--st-u-bg,#f4f4f5);padding:8px 12px;border-radius:8px"><code>X-Fdb-User-Token: &lt;your token&gt;</code></pre>
      <p class="hint" style="margin:6px 0 0">Get a token from <code>login</code> / <code>register</code> (or rotate it with <code>regenerate_token</code>).</p>
      <p class="hint" style="margin:10px 0 6px">Example - your credited factors (<code>contributions</code> needs a signed-in account):</p>
      <pre style="overflow-x:auto;background:var(--st-u-bg,#f4f4f5);padding:10px 12px;border-radius:8px"><code>curl -s https://factordb.com:4059/rpc \
  -H 'Content-Type: application/json' \
  -H 'X-Fdb-User-Token: &lt;your token&gt;' \
  -d '{"jsonrpc":"2.0","id":1,"method":"contributions","params":{"limit":10}}'</code></pre>
    </div>

    <div class="body" style="border-top:1px solid var(--hair)">
      <p class="fieldlabel">Batching</p>
      <p class="hint" style="margin:0">POST an <em>array</em> of request objects to run several calls in one round-trip; the response is an array of results in the same order, each matched by <code>id</code>. Calls in a batch run sequentially.</p>
    </div>

    <div class="body" style="border-top:1px solid var(--hair)">
      <p class="fieldlabel">Limits &amp; accounting</p>
      <p class="hint" style="margin:0">Every response carries a <code>X-Fdb-Resources: ids=…, time_ms=…, bytes=…, bg_ms=…</code> header summing what the request consumed. Requests are rate-limited and quota-bounded per client (ids created, wall time, bandwidth, background-check time); exceeding a budget returns HTTP <code>429</code>. See <a class="link" href="/limits.php">Limits</a> (including the rules for automated requests) and call <code>quota_status</code> for your current usage.</p>

      <p class="fieldlabel" style="margin-top:14px">Classic addresses (tools written for the old site)</p>
      <p class="hint" style="margin:0 0 6px">These keep working unchanged, over https and over plain http (many old scripts cannot speak https), with the old field names and the old one-line answers:</p>
      <table style="border-collapse:collapse;margin:0 0 6px">
        <tbody>
          <tr><td class="num" style="padding:1px 12px 1px 0;vertical-align:top"><code>/api?query=N</code>, <code>/api?id=N</code></td><td style="padding:1px 0;vertical-align:top"><span class="hint">the classic JSON answer <code>{id, status, factors:[[base, exp], …]}</code>, every digit of every factor</span></td></tr>
          <tr><td class="num" style="padding:1px 12px 1px 0;vertical-align:top"><code>/reportfactor.php</code></td><td style="padding:1px 0;vertical-align:top"><span class="hint"><code>id=</code> or <code>number=</code> plus <code>factor=</code> (GET or POST); answers "Factor submitted." etc.</span></td></tr>
          <tr><td class="num" style="padding:1px 12px 1px 0;vertical-align:top"><code>/report.php</code></td><td style="padding:1px 0;vertical-align:top"><span class="hint">POST <code>report=&lt;factor list&gt;</code> (elf / GMP-ECM output / <code>N = f1 * f2</code> lines); one line per number</span></td></tr>

          <tr><td class="num" style="padding:1px 12px 1px 0;vertical-align:top"><code>/cert/&lt;fid&gt;</code></td><td style="padding:1px 0;vertical-align:top"><span class="hint">the stored certificate as a text file (also <code>cert.php?id=</code>)</span></td></tr>

    <div class="body" style="border-top:1px solid var(--hair)">

With <code>snfs: true</code> and <code>detail: 2</code>, an open composite of 80-400 digits also carries <code>snfs</code>, the <code>snfs_poly</code> answer, so a page needs no second call.</p>
