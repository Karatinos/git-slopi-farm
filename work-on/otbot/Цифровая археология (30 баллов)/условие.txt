В огромном цифровом архиве хранятся данные, собранные за многие годы работы сети: документы, сообщения, изображения и тысячи других цифровых артефактов. Большинство посетителей никогда не задумываются, где именно всё это находится. Но вам предстоит заглянуть за кулисы архива.

Для хранения небольших объектов используется старое key-value хранилище, доступное по протоколу HTTP. Сервис работает на порту 2026 и, согласно сохранившейся документации, должен обрабатывать запросы следующим образом:

Запрос	Ответ
GET /{key}	Код 200, тело содержит содержимое ячейки. Если ключ отсутствует — код 404.
POST /{key} (тело с произвольными данными)	Код 202, тело содержит присланные данные, заголовок "X-Length" — длину данных в байтах. Переданные данные запоминаются по указанному ключу.
DELETE /{key}	Код 204, тело пустое, заголовок "X-Checksum" содержит хэш удалённых данных в виде XOR-суммы байт. Если ключ отсутствует — код 404.
SHOW / (заголовок "Thing")	Код 218 с сообщением "This is fine". Текстовое тело: "That is nice [thing].", где [thing] — содержимое заголовка "Thing".
Запросы, некорректные с точки зрения HTTP, сервер отклоняет с ошибкой 400.

Недавно при инвентаризации архива обнаружилась проблема: часть накопленных журналов могла быть получена от неисправных экземпляров сервиса. Сами данные уже давно удалены, поэтому проверить состояние хранилищ напрямую невозможно. Остались только записанные последовательности HTTP-запросов и ответов.

Каждый файл содержит журнал последовательной работы одного экземпляра хранилища. В начале записи хранилище было пустым.

Вам поручено провести цифровую экспертизу архивов. Для каждого журнала проверьте, соответствовал ли каждый ответ сервера описанному протоколу. Если хотя бы один ответ был сформирован неправильно, весь журнал считается полученным от неисправного экземпляра. Отклонениями, не нарушающими условия работы хранилища, спецификацию и стандарты HTTP, пренебречь.

Определите, какой процент журналов демонстрирует полностью корректную работу сервера.

Формат выходных данных: одно вещественное число. Ответ принимается с точностью до 2 знаков после запятой (пример: 54,12).

Задача проверяет навыки анализа произвольных массивов данных и работы с кодировками, что является частью финальной задачи.
